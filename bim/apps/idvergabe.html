IdVergabe

20 identification parameters on every element, in minutes

Platform | Revit · SQL Server master data
Stack | C# / .NET 4.8 · Revit API · WPF · SQL Server

Every element in a model needs a consistent set of identification parameters: element, unit, floor, room, assembly and parent IDs. By hand, that takes about a week for roughly 20,000 values. This add-in does it in about 5 minutes. It analyses the model's geometry, sorts elements into floors and spatial containers, reads the parameter definitions from a SQL Server master-data database, and calculates 20 parameters by hierarchy rules. It can run everything, or only the parameters you tick, with dependencies selected automatically.

How the model is read

Anatomy of an ElementID

Each part comes from a project setting or a calculated parameter. EinheitenNr is numbered counter-clockwise around the stair core; ElementNr by radial order within a container.

Design decisions

A week to 5 minutesAbout 20,000 values per run, set the same way every time.
Virtual model firstCalculations run on an in-memory copy of the project, which keeps Revit API load low. Values are written once, at the end.
One class per parameterEach of the 20 rules is isolated, so one rule can change without touching the rest.
Master data in SQLParameters are resolved by GUID from a central database, not hard-coded names.
Dependency resolutionTicking ElementID also selects the parameters it depends on.
Finds modelling errorsProblems surface in the final report, so they can be fixed early.
